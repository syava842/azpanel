# Этап 7: подписки, unlock-коды, клиентский портал — план

> **Исполнителям:** задачи по порядку; проверка — одна итоговая.

**Цель:** «доступ до» у пользователя (действует на всех его клиентов),
unlock-коды пачками, клиентский портал по постоянной ссылке без входа,
одноразовые ссылки на профиль с PIN, блокировка WireGuard снятием пира,
очередь уведомлений для бота (этап 8).

**Архитектура:** хранилище — миграция 3. Портал — отдельный набор
маршрутов `/p/…` в той же панели, без cookie сессии панели. Блокировка
WireGuard — у агента: сторож раз в `node.poll_seconds` убирает из
работающих интерфейсов пиров заблокированных клиентов (`wg set <if> peer
<key> remove`); `client.sh` при добавлении клиента пересобирает пиры из
конфига, и сторож снимает их снова — поэтому после каждого `client.sh`
сторож запускается сразу.

**Спецификация:** «Подписки и unlock-коды», «Клиентский портал»,
«Клиенты» (блокировка).

## Общие ограничения

- Код — латиница; интерфейс, ошибки, журнал — по-русски. `go 1.24`.
- Действующий срок клиента = меньший из `client_cards.access_until` и
  `users.access_until` владельца (любой NULL — не ограничивает). Сборщик
  (план 2а-3) блокирует и разблокирует по действующему сроку.
- Unlock-код: 16 символов `[A-Z2-9]` без похожих (`0`, `O`, `1`, `I`),
  показывается группами по 4 через дефис; ввод — без учёта регистра,
  дефисов и пробелов; хранится SHA-256 (у кода 80 бит энтропии, bcrypt не
  нужен); показывается один раз при выпуске. Погашение — одним `UPDATE …
  WHERE used_at IS NULL AND valid_until >= now`, проверка числа
  изменённых строк: два одновременных ввода — ровно один успех.
- Продление по коду: новый срок = max(сейчас, текущий срок) + `days`.
  Сертификат OpenVPN перевыпускается (`Renew`), только если после
  продления до конца сертификата остаётся меньше 30 дней.
- Токен портала — 32 случайных байта base64url, в базе SHA-256;
  «Перевыпустить ссылку» удаляет прежний. Ссылки: `/p/c_<токен>`
  (клиент), `/p/u_<токен>` (все клиенты пользователя).
- Попытки: 5 неверных unlock-кодов на один токен портала за час — ввод
  закрыт на час (429). То же для PIN одноразовой ссылки: 5 неверных —
  ссылка закрыта навсегда.
- Портал: `Cache-Control: no-store`, `Referrer-Policy: no-referrer`,
  тот же CSP, без JS. POST портала принимается, только если
  `Sec-Fetch-Site` — `same-origin` или `none`, либо `Origin` совпадает с
  хостом запроса; иначе 403. Ответы на неверный или отозванный токен —
  одинаковая 404 с задержкой 300 мс.
- Белый список IP панели (этап 6) на `/p/` **не** действует (спецификация:
  «наружу можно открыть только `/p/`»).
- Коммиты — от syava842@gmail.com, **без `Co-Authored-By` и подписей
  Claude**, по-русски.

### Задача 1: хранилище

**Файлы:** `internal/store/codes.go`, `portal.go`, `outbox.go`,
миграция 3, тесты.

```sql
ALTER TABLE users ADD COLUMN access_until INTEGER;
CREATE TABLE unlock_codes (id INTEGER PRIMARY KEY, hash TEXT NOT NULL UNIQUE,
  days INTEGER NOT NULL, valid_until INTEGER NOT NULL, user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  batch TEXT NOT NULL, created INTEGER NOT NULL, created_by TEXT NOT NULL,
  used_at INTEGER, used_node INTEGER, used_client TEXT, revoked INTEGER NOT NULL DEFAULT 0);
CREATE TABLE portal_links (hash TEXT PRIMARY KEY, kind TEXT NOT NULL CHECK (kind IN ('c','u')),
  node_id INTEGER, client TEXT, user_id INTEGER REFERENCES users(id) ON DELETE CASCADE, created INTEGER NOT NULL);
CREATE TABLE download_links (hash TEXT PRIMARY KEY, node_id INTEGER NOT NULL, client TEXT NOT NULL,
  pkind TEXT NOT NULL, variant TEXT NOT NULL, file TEXT NOT NULL,
  pin_hash TEXT, pin_fails INTEGER NOT NULL DEFAULT 0, expires INTEGER NOT NULL, used INTEGER NOT NULL DEFAULT 0,
  created INTEGER NOT NULL);
CREATE TABLE attempts (key TEXT NOT NULL, ts INTEGER NOT NULL);
CREATE INDEX attempts_key ON attempts(key, ts);
CREATE TABLE outbox (id INTEGER PRIMARY KEY, kind TEXT NOT NULL, user_id INTEGER, payload TEXT NOT NULL,
  created INTEGER NOT NULL, sent INTEGER);
```

Методы: выпуск пачки кодов (возвращает открытые коды один раз, в базу —
хеши), список кодов с фильтром по пачке и состоянию, отзыв; `RedeemCode(code, userID *int64, now) (Code, error)`
— атомарно, учитывает `user_id` кода (код на конкретного пользователя
гасится только для его клиентов), отозванные и просроченные — та же ошибка
«код неверен или уже использован»; ссылки портала (создать с заменой
прежней, найти по токену, удалить); одноразовые ссылки (создать, взять
по токену с проверкой срока, отметить использование атомарно, PIN с
счётчиком ошибок); `Attempt(key, now)`, `Attempts(key, since)`,
`PurgeAttempts(before)`; `Enqueue(kind, userID, payload)`,
`Pending(limit)`, `MarkSent(id)`; `EffectiveUntil(node, client) (*int64, error)`.

Тесты: два параллельных `RedeemCode` одного кода — ровно один успех;
код на пользователя не гасится для чужого клиента; просроченный и
отозванный — ошибка; одноразовая ссылка — второе скачивание отказ; PIN —
5 ошибок закрывают; `EffectiveUntil` — минимум двух сроков.

Коммит: «Хранилище: unlock-коды, ссылки портала, одноразовые ссылки, очередь уведомлений».

### Задача 2: блокировка WireGuard у агента

**Файлы:** `internal/antizapret/wgpeers.go` (разбор клиентов и публичных
ключей из `/etc/wireguard/*.conf` — сверь формат блоков `[Peer]` и
комментариев с именем клиента по `client.sh` в `testdata/`, контроллер
положит его туда), `internal/node/wgblock.go`, правки `api.go` (после
каждого `client.sh` — сразу проход сторожа; `SetBlocked` для клиента с
WireGuard — тоже), тесты.

- Сторож: для каждого интерфейса из `wg show interfaces`, кроме `warp-*`,
  — пиры, чьи ключи принадлежат заблокированным клиентам, удаляются
  `wg set <if> peer <key> remove`. Формат конфига (сверено на 94): перед
  каждым `[Peer]` строки `# Client = <имя>` и `# PrivateKey = …`, затем
  `PublicKey`, `PresharedKey`, `AllowedIPs`. Команды — через
  поле-функцию (подмена в тестах). Разблокировка — `wg-quick strip <if>`
  во временный файл (в `PrivateTmp` агента) и `wg syncconf <if> <файл>`:
  пир возвращается из конфига. Приватные ключи из комментариев не
  читаются в память дольше разбора и нигде не выводятся.
- `nodeapi.Result.Killed` при блокировке WG-клиента учитывает снятые пиры.
- Пометка в панели «блокировка действует только на OpenVPN» (план 2а-2)
  убирается.
- Тесты: заблокированный клиент с двумя интерфейсами — `remove` вызван на
  обоих; `warp-*` не трогается; после `client.sh` (создание другого
  клиента) сторож вызывается сразу; разблокировка вызывает `syncconf`.

Коммит: «Агент: блокировка WireGuard снятием пира».

### Задача 3: подписки и коды в панели

**Файлы:** `internal/panel/codes.go`, `subscription.go`, шаблоны
`codes.html`, `codes_new.html`, правки `user.html`, `client.html`,
`collector.go`; тесты.

- Пользователь: поле «доступ до» на странице пользователя (администратор).
- Сборщик: блок и разблок — по `EffectiveUntil`.
- Напоминания: сборщик раз в сутки (первый проход после 09:00 UTC) кладёт в
  `outbox` `access_expiring` для владельцев, у кого действующий срок
  кончается через 3 дня или сегодня (не повторять в тот же день — ключ
  в `meta`).
- «Коды» (администратор): выпуск пачки — количество 1–500, дней 1–3650,
  «код действует до» (дата), «на кого» (любой или пользователь); после
  выпуска — страница с кодами один раз и кнопка «Скачать .txt»
  (`Content-Disposition`); список пачек и кодов (не использован / использован
  кем и когда / просрочен / отозван), отзыв пачки или кода.
- Ввод кода администратором в карточке клиента («Продлить кодом») и
  пользователем в своей карточке.
- Продление: правило 30 дней для сертификата; журнал действий.
- Тесты: продление от прошлого и от будущего срока; сертификат
  перевыпускается только при запасе < 30 дней; код на пользователя для
  чужого клиента — отказ; напоминание кладётся один раз.

Коммит: «Панель: «доступ до» пользователя, unlock-коды, напоминания в очередь».

### Задача 4: портал

**Файлы:** `internal/panel/portal.go`, шаблоны `portal.html`,
`portal_help.html`, `dl.html`, правки `client.html`, `user.html`; тесты.

- `GET /p/c_<токен>`, `GET /p/u_<токен>`: на каждого клиента — статус
  (активен / заблокирован и причина / срок), трафик за 30 дней (итог и
  график из плана 2а-3), текущие подключения и лимит, скачать профили и
  QR (маршруты портала `/p/<токен>/profile/<kind>/<variant>/<file>` и
  `/qr/…` — только профили клиентов этой ссылки), поле unlock-кода.
- Инструкция: короткие шаги для Android, iOS, Windows, macOS (OpenVPN
  Connect / WireGuard / AmneziaWG — какие приложения и как импортировать
  файл или QR), статический шаблон.
- `POST /p/<токен>/unlock` — ограничение попыток по токену.
- Одноразовая ссылка `/dl/<токен>`: страница с PIN (если задан) и кнопкой
  «Скачать»; живёт 24 ч или одно скачивание.
- Карточка клиента (администратор): «Ссылка портала» — создать /
  перевыпустить (показывается полностью один раз, дальше — «создана …,
  перевыпустить»); «Одноразовая ссылка на профиль» — выбрать профиль,
  PIN по желанию; ссылка показывается один раз. Страница пользователя —
  ссылка `u_`.
- Адрес в ссылках — из настройки `panel.public_url` (добавить в конфиг,
  пусто — относительная ссылка и пометка «укажите адрес панели в
  настройках»).
- Тесты: портал не требует входа и не ставит cookie; неверный токен — 404
  с задержкой; перевыпуск убивает старую ссылку; профиль чужого клиента
  через портал — 404; POST unlock с `Sec-Fetch-Site: cross-site` — 403;
  6-я неверная попытка кода — 429; одноразовая ссылка — второе скачивание
  410; PIN — 5 ошибок закрывают; заголовки `no-store`/`no-referrer`.

Коммит: «Клиентский портал, одноразовые ссылки на профиль».
