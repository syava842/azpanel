# Этап 8: Telegram-бот и уведомления — план

> **Исполнителям:** задачи по порядку; проверка — одна итоговая.

**Цель:** бот панели по long polling: привязка аккаунтов, команды
администратора и пользователя, режимы для чужих аккаунтов, уведомления
администраторам, сводка и бэкапы по расписанию.

**Архитектура:** `internal/telegram` — тонкий клиент Bot API на
`net/http` (`getUpdates`, `sendMessage`, `sendDocument`, `sendPhoto`,
`answerCallbackQuery`, `editMessageText`, `getMe`) без сторонних
библиотек. `internal/panel/bot` — логика: разбор обновлений, меню на
inline-кнопках, состояние диалога в памяти. Уведомления — из `outbox`
(план этапа 7) и из сборщика. Бот запускается в процессе панели, если
задан токен.

**Спецификация:** «Telegram-бот», «Подписки и unlock-коды»
(напоминания, ввод кода в боте).

## Общие ограничения

- Код — латиница; тексты бота, ошибки, журнал — по-русски. `go 1.24`.
- Токен бота — `TELEGRAM_BOT_TOKEN` в `secrets.env`; в журнал и ошибки не
  попадает (ошибки `net/http` содержат URL с токеном — заменять токен на
  `<токен>` перед любой записью).
- Бот отвечает только в личных чатах (`chat.type == "private"`);
  обновления из групп и каналов игнорируются; уведомления в группы —
  только по chat ID из настроек.
- Права — те же, что в веб-панели (таблица этапа 6): пользователь видит
  только своих клиентов. Опасные действия (удалить клиента, перезагрузка
  сервера) — с подтверждением кнопкой «Да, …», подтверждение живёт 60 с.
- Привязка: «Привязать Telegram» на `/account` — одноразовый код 16 байт
  base64url, хранится SHA-256, живёт 10 минут; ссылка
  `https://t.me/<бот>?start=<код>`.
- Ввод unlock-кода в боте — те же правила, что в портале; ограничение
  попыток по Telegram ID (5 за час).
- Тесты — против поддельного Bot API (`httptest.Server`). Живая проверка
  — на тестовом боте владельца, когда он даст токен; бот StatusOpenVPN не
  трогать.
- Коммиты — от syava842@gmail.com, **без `Co-Authored-By` и подписей
  Claude**, по-русски.

### Задача 1: клиент Bot API

**Файлы:** `internal/telegram/client.go`, `types.go`, `client_test.go`.

- `New(token, baseURL string) *Client` (по умолчанию
  `https://api.telegram.org`), методы с `ctx`; `GetUpdates(ctx, offset,
  timeoutSec)` — long polling 50 с, HTTP-таймаут 60 с; ответ 429 — ждать
  `retry_after`; сетевые ошибки — повтор с нарастающей паузой до 60 с.
  Типы — только нужные поля (`Update`, `Message`, `CallbackQuery`,
  `Chat`, `User`, `InlineKeyboardMarkup`).
- Отправка файлов — `multipart/form-data`.
- Все ошибки проходят через `redact(err)` — токен вырезан.
- Тесты: разбор обновлений, offset растёт, 429 с `retry_after`,
  `sendDocument` multipart, токена нет в тексте ошибки при сетевом сбое.

Коммит: «Клиент Telegram Bot API».

### Задача 2: хранилище и настройки бота

**Файлы:** очередная миграция в `internal/store`,
`internal/store/telegram.go`, `internal/config` (раздел `[telegram]`), тесты.

```sql
ALTER TABLE users ADD COLUMN telegram_id INTEGER;
CREATE UNIQUE INDEX users_tg ON users(telegram_id) WHERE telegram_id IS NOT NULL;
CREATE TABLE tg_link_codes (hash TEXT PRIMARY KEY, user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE, expires INTEGER NOT NULL);
CREATE TABLE tg_requests (telegram_id INTEGER PRIMARY KEY, username TEXT, name TEXT, created INTEGER NOT NULL);
CREATE TABLE tg_banned (telegram_id INTEGER PRIMARY KEY, created INTEGER NOT NULL);
CREATE TABLE client_kinds (node_id INTEGER NOT NULL, name TEXT NOT NULL,
  allowed TEXT NOT NULL,  -- через запятую: openvpn, wireguard, amneziawg, antizapret, vpn; пусто — всё
  PRIMARY KEY (node_id, name));
```

`[telegram]` в `config.toml`: `enabled` (bool), `strangers`
(`closed` | `request`), `notify_chats` ([]int64), `notify` — включённые
виды (`node_down`, `load_high`, `reboot`, `sync_mismatch`, `hook_error`,
`limit_denials`, `antizapret_update`, `update_result`, `cert_expiring`,
`access_expiring`), пороги (`cpu_percent` 90, `mem_percent` 90,
`disk_percent` 90; дольше 5 минут), `summary_at` («09:00» UTC, пусто —
выкл.), `backup_every_days` (0 — выкл.), `backup_chats`. Проверка
значений в `Validate`.

Тесты: миграция; код привязки — один раз, просроченный — отказ;
`Validate` для неверного времени и неизвестного вида.

Коммит: «Хранилище и настройки бота».

### Задача 3: бот — привязка, меню, команды

**Файлы:** `internal/panel/bot/bot.go`, `handlers.go`, `menu.go`,
`bot_test.go`; правки `account.html` (привязка и отвязка), `user.html`
(администратор видит привязку), `client.html` (разрешённые типы профилей
для бота).

- `/start <код>` — привязка; непривязанный без кода — по режиму:
  `closed` — молчать; `request` — «заявка отправлена», запись в
  `tg_requests` и уведомление администраторам с кнопками «Одобрить» (выбор
  пользователя или создание нового) и «Отклонить» / «Заблокировать ID».
  Заблокированные ID — молчать всегда.
- Меню администратора: «Клиенты» (список с онлайн, по 20, поиск
  сообщением), карточка клиента (статус, срок, трафик 30 дн.; кнопки:
  профиль, QR, блок/разблок, продлить на 30/90/365, лимит подключений
  1/2/3/5/снять, удалить — с подтверждением), «Создать клиента» (диалог:
  имя → тип → дни), «Узел» (агент, службы, ресурсы), «Бэкап»
  (`client.sh 8` задачей агента → файл в чат), «Перезагрузка сервера»
  (подтверждение; агент: `POST /v1/system/reboot` → `systemctl reboot`
  через механизм задач этапа 3).
- Меню пользователя: свои клиенты, профиль и QR (только разрешённые в
  `client_kinds`), срок, «Ввести код».
- Профиль — `sendDocument`, QR — `sendPhoto` (PNG тем же кодом, что в
  панели).
- Каждое действие — в журнал действий (`user` — логин, `ip` — `tg:<id>`).
- Тесты (поддельный Bot API, поддельный агент, временная база): привязка;
  непривязанный в `closed` — ни одного `sendMessage`; `request` — заявка
  и уведомление; пользователь не видит чужого клиента и кнопок
  администратора; удаление требует подтверждения, подтверждение истекает
  через 60 с; групповой чат игнорируется; ввод кода — продление и лимит
  попыток.

Коммит: «Telegram-бот: привязка, меню администратора и пользователя».

### Задача 4: уведомления, сводка, бэкапы

**Файлы:** `internal/panel/bot/notify.go`, `schedule.go`, правки
`collector.go`, тесты.

- Источники: `outbox` (этап 7 и следующие); сборщик — `node_down` и
  «снова доступен» (агент не отвечает 3 прохода подряд / снова отвечает),
  `load_high` (порог дольше 5 минут; одно уведомление до возврата ниже
  порога), `reboot` (uptime уменьшился), `limit_denials` (сводка раз в час
  из `Denials`: имя — число отказов), `cert_expiring` (сертификат OpenVPN
  кончается через 7 дней — раз в сутки на клиента). `hook_error`,
  `sync_mismatch`, `antizapret_update`, `update_result` кладут в `outbox`
  этапы 4, 5, 2в; здесь — только доставка.
- Доставка: привязанным администраторам и `notify_chats`; выключенный
  вид — запись помечается отправленной без отправки. Ошибка — повтор
  при следующем проходе; после 10 неудач — запись в журнал и отметка.
- `access_expiring` — владельцу клиента, если он привязан.
- Сводка в `summary_at`: онлайн сейчас, трафик за сутки (топ-10), узел.
- Бэкап раз в `backup_every_days`: задача агента `client.sh 8`, файл — в
  `backup_chats`; в `/opt/azpanel/backup/` хранятся 14 последних.
- Тесты: каждый вид кладётся и доставляется; выключенный не уходит;
  `load_high` не повторяется; сводка в нужную минуту (подменённое
  время); повтор после ошибки.

Коммит: «Бот: уведомления, сводка и бэкапы по расписанию».

### Задача 5: запуск и проверка

- `panel.Run`: есть `TELEGRAM_BOT_TOKEN` и `telegram.enabled` — бот
  стартует (`getMe` → имя бота для ссылок привязки); ошибка — `Warn`,
  панель работает без бота.
- Живая проверка (контроллер) — когда владелец даст токен тестового бота:
  привязка администратора, список клиентов, профиль, бэкап в чат. До
  токена — только тесты; записать это в итог.

Коммит: «Панель: запуск бота».
