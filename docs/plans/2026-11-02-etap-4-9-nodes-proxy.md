# Этапы 4 и 9: несколько серверов, синхронизация, прокси-узлы — план

> **Исполнителям:** задачи по порядку; проверка — одна итоговая.

**Цель:** панель управляет несколькими узлами по TLS; группы
синхронизации (основной + реплики) со сверкой, выравниванием,
назначением основного; обновление AntiZapret по группе; прокси-агент
`azpanel proxy` для VPS с `proxy.sh`; режимы установки «только узел»,
«только панель», «только прокси-агент».

**Ограничения по стендам:** 192.0.2.193 — боевой основной, на нём без
отдельного разрешения владельца — **только чтение**; 94 — запасной, можно
всё. Российского VPS нет: прокси-агент проверяется только тестами (в том
числе против `iptables-save` из `testdata/`, снятого по образцу
`proxy.sh`). Живая проверка удалённого агента — панель на втором хосте
стенда (см. задачу 6).

**Спецификация:** «Синхронизация серверов», «Прокси-узлы», «Агент»
(TLS, белый список), «Установка azpanel» (типы установки, ключ узла).

## Общие ограничения

- Код — латиница; интерфейс, ошибки — по-русски. `go 1.24`.
- Агент вне хоста панели слушает один порт по TLS (самоподписанный
  сертификат агента, панель закрепляет отпечаток SHA-256 при добавлении
  узла; несовпадение — отказ с понятной ошибкой «сертификат узла
  сменился»), белый список IP панели, токен узла — как сейчас.
- «Ключ узла» для установки — строка `azn1.<base64url(JSON{panel_ip,
  token})>`: панель генерирует при «Узлы → Добавить», показывает готовую
  команду `azpanel install --non-interactive AZPANEL_MODE=node
  AZPANEL_NODE_KEY=…`; узел после установки печатает отпечаток своего
  сертификата, панель просит сверить.
- Изменения клиентов, маршрутизации и `setup` в группе — только на
  основном; агент реплики их отклоняет (409 «узел — реплика группы …»),
  панель прячет кнопки.
- Копирование на реплики — через API агентов (панель читает файлы у
  основного и пишет на реплику), без SSH между серверами. Перед
  «Выровнять» — бэкап реплики `client.sh 8`.
- Ключи WARP в `setup`, история трафика, мониторинг — свои у каждого
  сервера, не копируются.
- Коммиты — от syava842@gmail.com, **без `Co-Authored-By` и подписей
  Claude**, по-русски.

### Задача 1: TLS агента и узлы в панели

**Файлы:** `internal/node/tlsserve.go`, `internal/config` (`node.listen_tls`,
`node.allow_ips`), `internal/nodeapi` (клиент с закреплённым
отпечатком), `internal/store` (миграция: `nodes` + `fingerprint`,
`role`, `group_id`; `groups`), `internal/panel/nodes.go`, шаблоны, тесты.

- Агент: при `listen_tls` — сертификат в `etc/tls/node.{crt,key}`
  (создаётся при первом старте), белый список IP — до TLS-рукопожатия
  (`net.Listener` обёрткой), по-прежнему токен.
- Панель: «Узлы» — список (имя, адрес, версия агента, протокол, связь,
  роль в группе), добавить (ключ и команда), удалить, проверить связь.
  Все страницы клиентов, «Сейчас», маршрутизации, задач — с выбором узла
  (`?node=<id>`, по умолчанию первый); сборщик — по всем узлам
  параллельно; `node_id` в данных уже есть с плана 2а-3.
- Протокол: агент протокола панели или предыдущего — работа; старше —
  «обновите агент», команды кроме обновления не шлются.
- Тесты: отпечаток не совпал — ошибка; адрес не в белом списке —
  соединение закрыто до TLS; сборщик по двум поддельным узлам; страницы с
  `?node=`.

Коммит: «Несколько узлов: TLS агента, отпечаток, узлы в панели».

### Задача 2: файлы синхронизации у агента

**Файлы:** `internal/node/syncfiles.go`, маршруты `/v1/sync/…`, тесты.

- Набор (спецификация): `/etc/openvpn/easyrsa3` целиком (включая
  `crl.pem`), серверные конфиги и ключи WG/AmneziaWG (`antizapret.conf`,
  `vpn.conf`, `key`), файлы профилей клиентов, `.ovpn` байт в байт,
  `config/*.txt`, `/etc/knot-resolver/custom*.lua`, `setup` без ключей
  WARP, `limits.json`. (`banned_clients` в нынешнем AntiZapret нет —
  пропускается, если файла нет.)
- `GET /v1/sync/manifest` — список файлов с SHA-256, размером, правами;
  `GET /v1/sync/file?path=` — содержимое (путь — только из манифеста);
  `POST /v1/sync/apply` — tar-архив с файлами набора (до 256 МБ): агент
  проверяет, что каждый путь из набора, пишет атомарно с правами, затем
  перезапускает службы (OpenVPN-экземпляры, `wg-quick@*`, `kresd@*`) и
  возвращает новый манифест. `setup` реплики: ключи WARP сохраняются
  свои, остальные — из архива.
- Отклонение изменяющих маршрутов на реплике (роль приходит от панели в
  `POST /v1/sync/role`, хранится в `data/role.json`).
- Тесты: путь вне набора — 400; ключи WARP реплики сохранены; роль
  «реплика» — `POST /v1/clients` 409.

Коммит: «Агент: набор файлов синхронизации, применение и роль».

### Задача 3: группы в панели

**Файлы:** `internal/panel/groups.go`, `sync.go`, шаблоны, тесты.

- Группа: основной + реплики; «Сверить» — манифесты основного и каждой
  реплики, расхождения по файлам, плюс запущенное состояние (`wg show`,
  список клиентов); уведомление `sync_mismatch`.
- После любого изменения клиентов/маршрутизации/`setup` на основном —
  копирование затронутых файлов на реплики (по манифесту) и перезапуск
  нужных служб; ошибка — пометка группы и уведомление.
- «Выровнять» реплику: `client.sh 8` на ней, полная замена набора с
  основного, перезапуск, сверка.
- «Назначить основным»: реплика → основной, прежний → реплика (или
  удалить из группы, если недоступен).
- Адреса для клиентов: несколько `remote` в `.ovpn` (список на группу,
  порядок задаётся) или один домен — вписывается в `OPENVPN_HOST` и
  `WIREGUARD_HOST` основного, `client.sh 7`, затем синхронизация. DNS
  панель не настраивает.
- Обновление AntiZapret в группе (план этапов 5, 10, 11): по одному,
  сначала реплики, основной последним; следующий — только после `ok`
  предыдущего.
- Тесты на поддельных агентах: сверка находит расхождение; изменение на
  основном уходит на реплику; выравнивание делает бэкап первым;
  назначение основного меняет роли; обновление группы останавливается на
  первой ошибке.

Коммит: «Группы синхронизации: сверка, выравнивание, основной, обновление по группе».

### Задача 4: прокси-агент

**Файлы:** `internal/proxy/` (`iptables.go` — разбор `iptables-save -t
nat`, правила DNAT `proxy.sh` для портов OpenVPN 80, 443, 504, 508,
50080, 50443 и WG/AmneziaWG 540, 580, 51080, 51443, 52080, 52443;
`conntrack.go` — `/proc/net/nf_conntrack` или `conntrack -L` → «порт на
прокси → адрес клиента»; `apply.go` — смена адреса назначения),
`cmd/azpanel` режим `proxy`, юнит `azpanel-proxy.service`, панель —
«Прокси», тесты.

- Состояние: жив ли, проброшенные порты, текущие адреса назначения
  OpenVPN и WG, число соединений, нагрузка (тот же `sysinfo`).
- Смена адреса назначения: снимок `iptables-save`, правка только
  DNAT-правил `proxy.sh` (по портам из списка), `iptables-restore`; ошибка
  — восстановление снимка; успех — сохранение как у `proxy.sh`
  (`netfilter-persistent save`).
- Перекрёстная проверка: IP прокси есть в `allow-ips.txt` серверов
  назначения (через API агента узла, план этапа 3) — иначе предупреждение
  и кнопка «добавить».
- Настоящий адрес клиента: панель показывает его рядом с сессией в
  «Сейчас», сопоставляя порт.
- Переключение при отказе: основной группы недоступен дольше заданного
  (настройка, по умолчанию выключено, 2 минуты) — адрес назначения
  прокси на реплику, уведомление; обратно — вручную.
- Список `remote` в `.ovpn` группы может включать прокси.
- Порт агента прокси по умолчанию 9101, TLS и токен — как у узла.
- Тесты на `testdata/iptables-save.txt` (составь по `proxy.sh`
  AntiZapret — контроллер положит его копию в `testdata/`): разбор
  правил; смена адреса меняет только DNAT своих портов; ошибка restore —
  откат; разбор conntrack.

Коммит: «Прокси-агент: состояние, смена адреса назначения, адреса клиентов, переключение».
