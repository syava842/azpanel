# Этап 2в: самообновление azpanel — план

> **Исполнителям:** задачи по порядку; проверка — одна итоговая.

**Цель:** релизы с подписью ed25519, проверка обновлений раз в 6 часов,
обновление кнопкой в панели и `azpanel update` с бэкапом, миграциями
конфига и базы и откатом при упавшем `/healthz`; обновление агентов из
панели.

**Спецификация:** «Обновление azpanel», «Репозиторий» (релизы, токен
GitHub).

## Общие ограничения

- Код — латиница; интерфейс, ошибки — по-русски. `go 1.24`.
- Версия — semver, вшивается `-ldflags "-X main.version=…"`; сборка без
  версии — `dev`, такая сборка обновлений не предлагает и не ставит.
- Открытый ключ ed25519 вшит в бинарник (`internal/update/pubkey.go`);
  закрытый — только на машине разработчика (`~/.azpanel-release.key`, в
  репозиторий не попадает: `.gitignore` и проверка в `release.sh`).
- Без верной подписи и совпавшего `.sha256` обновление не ставится.
- Токен GitHub (fine-grained, `Contents: Read`) — `GITHUB_TOKEN` в
  `secrets.env`; без него проверка выключена; в журнал и ошибки не
  попадает.
- Коммиты — от syava842@gmail.com, **без `Co-Authored-By` и подписей
  Claude**, по-русски.

### Задача 1: сборка релиза и подпись

**Файлы:** `scripts/release.sh`, `cmd/azpanel-sign/main.go` (утилита
разработчика: `keygen`, `sign <файл>`), `internal/update/pubkey.go`,
`internal/update/verify.go`, `CHANGELOG.md`, тесты.

- `release.sh <версия>`: проверка чистого дерева и тега; сборка
  `linux/amd64`, `linux/arm64` (`CGO_ENABLED=0`, `-trimpath`,
  `-ldflags "-s -w -X main.version=<версия>"`); архивы
  `azpanel_<версия>_linux_<arch>.tar.gz`; `SHA256SUMS`; подпись
  `SHA256SUMS.sig` (ed25519 по файлу `SHA256SUMS`); раздел версии из
  `CHANGELOG.md` — в описание релиза; публикация `gh release create`
  только по флагу `--publish`, без него — файлы в `dist/`.
- `Verify(pub ed25519.PublicKey, sums, sig []byte, file string, data []byte) error`.
- Тесты: подпись чужим ключом — отказ; подменённый архив — отказ;
  отсутствующая строка в `SHA256SUMS` — отказ.

Коммит: «Релизы: сборка, SHA256SUMS и подпись ed25519».

### Задача 2: миграции конфига

**Файлы:** `internal/config/migrate.go`, тесты.

- Цепочка `migrations []func(map[string]any) (map[string]any, []Question, error)`
  — по одной на `N → N+1`; работают с разобранным TOML как с картой, чтобы
  переименования не теряли значения. Миграция может вернуть `Question` —
  обязательное значение без умолчания (ключ, текст, проверка).
- `Migrate(data []byte, answers map[string]string) ([]byte, []Question, error)`:
  есть вопросы без ответов — вернуть их, ничего не меняя.
- Для 1 → 2 (уже существующей) — явная миграция вместо нынешнего
  «умолчания подставятся».
- Тест на каждую миграцию (`testdata/config-v<N>.toml` → новый файл);
  вопрос без ответа; ответ проверяется.

Коммит: «Конфиг: цепочка миграций с вопросами».

### Задача 3: обновление

**Файлы:** `internal/update/github.go`, `apply.go`, `check.go`,
`cmd/azpanel/updatecmd.go`, тесты.

- `Latest(ctx, token)` — `GET /repos/syava842/azpanel/releases/latest`;
  скачивание ассетов через API (`Accept: application/octet-stream`).
- `Apply(opts)`:
  1. скачать архив своей архитектуры, `SHA256SUMS`, `.sig`; проверить;
  2. бэкап `etc/` и `data/` в `backup/update-<старая>-<дата>.tar.gz`
     (база — через `VACUUM INTO`, не копией живого файла); текущий
     бинарник — `bin/azpanel.prev`;
  3. миграции конфига (вопросы — в панели формой, в `azpanel update` —
     вопросом; без ответов не продолжать);
  4. замена бинарника атомарно, перезапуск `azpanel-panel` и
     `azpanel-node` на этом хосте;
  5. новый процесс сам применяет миграции базы при старте;
  6. проверка `/healthz` 30 с и `/v1/info` агента с новой версией; не
     прошла — вернуть `azpanel.prev`, `etc/`, `data/` из бэкапа,
     перезапуск, уведомление `update_result` с причиной.
  Выполняется задачей `systemd-run` (механизм этапа 3), чтобы пережить
  перезапуск самой панели; журнал — `log/tasks/`.
- Проверка раз в 6 часов: «есть обновление x.y.z» с изменениями из
  описания релиза — на странице «Обновление» и в шапке; уведомление
  вида `azpanel_update` (добавить в список видов бота).
- `azpanel update [--check] [--yes]` — то же из консоли.
- Агенты на других хостах (после этапа 4): панель сама скачивает и
  проверяет архив и передаёт агенту `POST /v1/update` (multipart:
  бинарник, `SHA256SUMS`, `.sig`; предел тела этого маршрута — 64 МБ);
  агент **сам** проверяет подпись вшитым ключом и выполняет шаги 2, 4, 6
  у себя. Агент протокола старше предыдущего — пометка «обновите агент»,
  другие команды ему не шлются.
- Тесты: поддельный GitHub (`httptest`); неверная подпись — отказ без
  изменений; упавший `/healthz` — откат, файлы совпадают с исходными;
  миграция с вопросом без ответа — отказ без изменений; `dev`-сборка
  обновлений не предлагает; агент отвергает бинарник с чужой подписью.

Коммит: «Самообновление панели и агентов с откатом».
