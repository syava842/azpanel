> **Исполнителям:** задачи по порядку; проверка — одна итоговая.

**Цель:** панель открывается из браузера по HTTPS без SSH-туннеля; все
настройки меняются в вебе; полный мастер `azpanel install` с вопросами из
спецификации, режим без вопросов, `azpanel doctor`, `uninstall` с уборкой
nginx.

**Сверено на 94 (02.11.2026):** nginx, `sites-enabled/` —
`default`, `vpn.test` (443 ssl, Let's Encrypt
`/etc/letsencrypt/live/vpn.test/`, `location /status/` —
StatusOpenVPN), `warper-web` (80 с `/.well-known/acme-challenge/`, 6060
ssl); `certbot` есть; `OPENVPN_BACKUP_TCP=n`. Значит, панели нужен
префикс пути (`/azpanel/`) рядом со StatusOpenVPN.

**Спецификация:** «Установка azpanel», «Настройки», «Панель».

## Общие ограничения

- Код — латиница; вопросы мастера, интерфейс, ошибки — по-русски. `go 1.24`.
- Панель по-прежнему слушает только петлевой адрес; наружу — nginx.
- Правка nginx: свой фрагмент — отдельный файл
  `/etc/nginx/snippets/azpanel.conf`; в чужой файл добавляется **одна**
  строка `include /etc/nginx/snippets/azpanel.conf; # azpanel` внутрь
  выбранного `server { … }`; перед правкой — копия `<файл>.bak-<дата>`;
  `nginx -t` не прошёл — возврат копии, отказ; прошёл — `systemctl reload
  nginx`. `uninstall` убирает строку и фрагмент тем же порядком.
- До итогового подтверждения мастер ничего не меняет на сервере
  (проверяется тестом: все побочные действия — через поле-функцию).
- Секреты в вебе не показываются целиком («задан, заканчивается на …» и
  «Заменить»); в экспорт — только по явному выбору.
- Опасные настройки (адрес и порт панели, белый список IP, `base_path`,
  доверенные прокси) — через механизм таймера возврата этапа 6 (2 минуты
  на подтверждение).
- Коммиты — от syava842@gmail.com, **без `Co-Authored-By` и подписей
  Claude**, по-русски.

### Задача 1: префикс пути и доверенный прокси

**Файлы:** `internal/config` (`panel.base_path` — пусто или `/x/`,
`panel.trusted_proxies` — список CIDR, по умолчанию `127.0.0.1/32`,
`::1/128`), `internal/panel/` — все шаблоны и редиректы, `server.go`,
`auth.go`, тесты.

- Все ссылки шаблонов — через функцию `{{url "/clients/…"}}`, все
  редиректы — `s.url(…)`, cookie — `Path=<base_path>`, статика —
  `{{url "/static/style.css"}}`. Обработчик снимает префикс
  (`http.StripPrefix`); запрос без префикса — 404.
- Адрес клиента: `RemoteAddr` из `trusted_proxies` и есть
  `X-Forwarded-For` — самый правый адрес, не входящий в доверенные; иначе
  `RemoteAddr`. `X-Forwarded-Proto: https` учитывается только от
  доверенного. Это закрывает находку M1 плана 2а-2 (ограничитель попыток
  по настоящему адресу).
- Тест-сторож: обход всех шаблонов — ни одного `href="/`, `action="/`,
  `src="/` без `url`; с `base_path=/azpanel/` — все страницы и редиректы
  с префиксом; XFF от недоверенного адреса игнорируется; цепочка XFF с
  подделанным левым адресом — берётся правый недоверенный.

Коммит: «Панель: префикс пути и доверенный прокси».

- Тесты: неверное значение — отказ у поля, файл не тронут; сторож

### Задача 3: TLS и nginx

**Файлы:** `internal/install/nginx.go`, `tls.go`, тесты.

- `FindServers(dir string) ([]NginxServer, error)` — разбор
  `sites-enabled/*` и `conf.d/*.conf`: блоки `server` (по скобкам,
  комментарии и строки в кавычках учитываются), их `listen`,
  `server_name`, `ssl_certificate`, файл и строки блока.
- `Snippet(basePath, upstream string) string` — `location <base_path> {
  proxy_pass http://<upstream>; proxy_set_header Host $host;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme; proxy_read_timeout 900s;
  client_max_body_size 2m; }`.
- `InsertInclude(file string, server NginxServer) error` / `RemoveInclude` —
  одна строка с меткой `# azpanel`; повторный вызов не дублирует.
- Отдельный порт: `ServerBlock(port int, cert, key, serverName string)` —
  свой файл `sites-available/azpanel` + ссылка в `sites-enabled`.
- `Apply` — копия, запись, `nginx -t`, при ошибке — возврат; `reload`.
  Команды и файловые операции — через поля-функции.
- TLS: `SelfSigned(hosts []string, dir string)` (ECDSA P-256, 825 дней,
  `crypto/x509`); Let's Encrypt — `certbot certonly --webroot -w
  /var/www/azpanel-acme -d <домен> --non-interactive --agree-tos -m
  <почта>` с временным `location /.well-known/acme-challenge/` во
  фрагменте на 80, если на 80 уже слушает nginx; 80 свободен — `certbot
  certonly --standalone`; 80 занят не nginx (AntiZapret при
  `OPENVPN_BACKUP_TCP=y`) — отказ с причиной. Есть сертификат на домен в
  `/etc/letsencrypt/live/<домен>` — предложить его.
- Тесты на копиях настоящих конфигов 94 в `testdata/nginx/` (контроллер
  положит их; секретов там нет — только пути к сертификатам): найдены три
  файла и блок `vpn.test:443`; вставка в блок 443 и удаление
  возвращают файл байт в байт; ошибка `nginx -t` — файл восстановлен;
  самоподписанный сертификат разбирается `x509`.

Коммит: «Установка: nginx-фрагмент и сертификаты».
