# Этап 3: маршрутизация и `setup` — план

> **Исполнителям:** задачи по порядку; проверка — одна итоговая.

**Цель:** редактор списков `config/*.txt` с проверкой строк, применение
`doall.sh` фоновой задачей с журналом, «обновить списки сейчас», правка
ключей `setup` с применением средствами AntiZapret.

**Архитектура:** агент получает механизм фоновых задач: долгие команды
запускаются через `systemd-run` отдельным временным юнитом — вне
песочницы агента (`ProtectSystem=strict` не дал бы `doall.sh` писать в
`/etc/knot-resolver` и sysctl), задача переживает перезапуск агента, вывод
— в `/opt/azpanel/log/tasks/<дата>-<вид>-<id>.log`. Списки и `setup`
агент правит сам, атомарно, с копией в `backup/`. Панель — страницы
«Маршрутизация» и «Задачи».

**Сверено на 94 (02.11.2026):** 18 файлов `config/*.txt`;
`include-adblock-hosts.txt` — 382 608 строк, 7,7 МБ (редактор не может
грузить файл целиком); `parse.sh` убирает пробелы и `\r`, пропускает
строки, начинающиеся с пунктуации (комментарии `#`), у `*-rpz.txt`
комментарии — `;`. `antizapret.service`: `ExecStartPre=up.sh`,
`ExecStopPost=down.sh`. Ключи `setup` читают: `update.sh`/`parse.sh`
(`*_INCLUDE`, `*_ADBLOCK`, `ROUTE_ALL`, `CLEAR_HOSTS`) — применяет
`doall.sh`; только `up.sh` (`SSH_PROTECTION`, `ATTACK_PROTECTION`,
`SCAN_PROTECTION`, `TORRENT_GUARD`, `RESTRICT_FORWARD`, `CLIENT_ISOLATION`,
`OPENVPN_BACKUP_UDP`, `OPENVPN_BACKUP_TCP`, `WIREGUARD_BACKUP`,
`TXQUEUELEN`, `WARP_PROTECTION`) — перезапуск `antizapret`;
`OPENVPN_HOST`, `WIREGUARD_HOST` — `client.sh 7` (профили); режимы WARP
читает `up.sh` и сам создаёт `warp-*.conf` — перезапуск `antizapret` и
`doall` (спецификация считала, что нужен `setup.sh`: уточнено по
скриптам); `MTU` записан в конфиги OpenVPN, `ANTIZAPRET_DNS` — в
настройку kresd, адреса, интерфейсы, `*_ENABLE` и ключи OpenVPN —
повторный `setup.sh` (этап 5), в этом плане — только показ.

**Спецификация:** «Маршрутизация», правило работы с AntiZapret
(«Архитектура»).

## Общие ограничения

- Код — латиница; интерфейс, ошибки, журнал — по-русски. `go 1.24`.
- Агент правит только `config/*.txt` и `setup` в `node.antizapret_dir`;
  имя файла — строго из списка, найденного в каталоге (`^[a-z0-9-]+\.txt$`),
  никаких путей из запроса.
- Перед каждой записью — копия в
  `/opt/azpanel/backup/antizapret/<имя>.<UTC-время>`; хранятся 20
  последних копий на файл. Запись — атомарно, права и владелец прежние.
- Ключи с секретами (`*_PRIVATE_KEY`) не отдаются в API вовсе.
- Одновременно — одна задача AntiZapret (`doall`, `restart`, `profiles`);
  вторая — 409 «уже идёт задача …». `client.sh` из API клиентов во время
  задачи `profiles` — 409.
- Задачи пишутся в журнал действий панели.
- На 94 можно всё; после проверки вернуть `config/*.txt` и `setup` к
  исходным байтам (сверить `sha256sum` до и после).
- Коммиты — от syava842@gmail.com, **без `Co-Authored-By` и подписей
  Claude**, по-русски.

### Задача 1: фоновые задачи агента

**Файлы:** `internal/node/tasks.go`, `tasks_test.go`, маршруты в
`api.go`, типы в `nodeapi`.

```go
type Task struct {
	ID       string    `json:"id"`        // 12 hex
	Kind     string    `json:"kind"`      // doall | restart | profiles (этапы 5, 10, 11 добавят свои)
	Started  time.Time `json:"started"`
	Finished *time.Time `json:"finished,omitempty"`
	ExitCode *int      `json:"exit_code,omitempty"`
	Log      string    `json:"log"`       // путь журнала
}
```

- `Tasks.Start(kind string, argv []string) (Task, error)` — запуск
  `systemd-run --unit=azpanel-task-<id> --collect --quiet --wait
  --property=StandardOutput=append:<журнал> --property=StandardError=append:<журнал>
  --working-directory=<antizapret_dir> -- <argv>` в горутине; код выхода
  `systemd-run --wait` — код задачи. Запуск команды — через поле-функцию
  (подменяется в тестах). Состояние задач — `data/tasks.json` (последние
  100), чтобы список пережил перезапуск агента; задача, бывшая «идёт» при
  старте агента, проверяется `systemctl is-active azpanel-task-<id>` и
  дожидается или помечается «прервана».
- Журналы задач старше 30 дней удаляются при старте и раз в сутки
  (спецификация «Раскладка»).
- API: `GET /v1/tasks` (последние 100, новые сверху), `GET /v1/tasks/{id}`
  (+ поле `tail` — последние 64 КБ журнала), `POST /v1/routing/apply`
  (doall), `POST /v1/antizapret/restart`, `POST /v1/clients/profiles/rebuild`
  (`client.sh 7`).
- Тесты: вторая задача при идущей — 409; код выхода и время окончания
  записаны; `tasks.json` переживает новый экземпляр; прерванная задача;
  `tail` не больше 64 КБ; ротация журналов по возрасту.

Коммит: «Агент: фоновые задачи через systemd-run с журналом».

### Задача 2: списки маршрутизации у агента

**Файлы:** `internal/antizapret/routing.go`, `routing_test.go`,
`internal/node/routing_api.go`, тесты, типы в `nodeapi`.

- Виды файлов по имени: `*-hosts.txt` → `hosts`, `*-ips.txt` → `ips`,
  `*-rpz.txt` → `rpz`. Описание для интерфейса — таблица по имени
  (по-русски: «домены через AntiZapret», «исключить домены», «блокировка
  рекламы — добавить», «IP через AntiZapret», «разрешённые IP (защита от
  сканирования)», …; неизвестный — пустое).
- Проверка строки (после того же отсечения, что делает `parse.sh`:
  убрать `\r` и пробелы по краям; пустые и комментарии — пропуск, но
  сохраняются в файле): `hosts` — домен (метки `[a-z0-9-]`, 1–63, не с
  дефиса, всего ≤ 253, хотя бы одна точка; допускается ведущая точка и
  одиночная `.` только в `include-hosts.txt`/`include-warp-hosts.txt` —
  `parse.sh` её разрешает), регистр приводится к нижнему; `ips` — IPv4
  или IPv4/CIDR (`netip.ParsePrefix`, адрес приводится к сети); `rpz` —
  `<домен> CNAME <цель>` или `*.<домен> CNAME <цель>`, цель — `.` или
  `rpz-passthru.` или домен. Ошибка — номер строки и причина.
- `GET /v1/routing/files` → `[{name, kind, title, lines, bytes}]`.
- `GET /v1/routing/files/{name}?q=&offset=&limit=` → строки (без
  комментариев и пустых), отфильтрованные подстрокой, страница
  (`limit` ≤ 1000), всего найдено.
- `PATCH /v1/routing/files/{name}` `{add: [...], remove: [...]}` —
  добавить новые (дубликаты пропускаются), удалить точные совпадения;
  комментарии и порядок прочих строк сохраняются; ответ — сколько
  добавлено, удалено, пропущено, ошибки построчно (при ошибке файл не
  меняется).
- `PUT /v1/routing/files/{name}` `{content}` — полная замена для файлов
  до 1 МБ (больше — 413 «редактируйте по строкам»).
- `GET /v1/routing/backups/{name}` — список копий; `POST
  /v1/routing/backups/{name}/{stamp}/restore` — вернуть копию (сама
  возвращаемая версия перед этим тоже копируется).
- Тесты: каждая проверка строки с примерами годных и негодных; PATCH
  сохраняет комментарии и порядок; ошибка — файл не тронут; большой файл
  (200 000 строк во временном каталоге) — PATCH укладывается в 2 с и
  страница с `q` работает; PUT больше 1 МБ — 413; имя `../setup` и
  несуществующее — 404; копии: 21-я вытесняет первую; восстановление.

Коммит: «Агент: списки маршрутизации — просмотр, правка, копии, проверка строк».

### Задача 3: ключи `setup` у агента

**Файлы:** `internal/antizapret/setupkeys.go`, тесты; маршруты в агенте.

- Таблица ключей: имя → вид значения, способы применения (список),
  описание по-русски. Неизвестный ключ — только чтение. Сверено по
  скриптам на 94 (какой скрипт читает ключ):
  - `ANTIZAPRET_WARP`, `VPN_WARP`: `enum n|1|2|3|4` (`up.sh` различает
    2 — весь выход через WARP, 3 и 4 — по меткам; 1 и `n` — без WARP),
    применение `restart` + `doall` (`up.sh` сам создаёт
    `/etc/wireguard/warp-*.conf`, `parse.sh` читает режим);
  - `DNS_WARP`: `enum n|y` (сверить в `up.sh`), `restart`;
  - `WARP_MTU`: `int 1280..1500`, `restart`;
  - `ANTIZAPRET_ADBLOCK`, `VPN_ADBLOCK`, `ROUTE_ALL`, `CLEAR_HOSTS`,
    все `*_INCLUDE`: `yn`, `doall`;
  - `ATTACK_PROTECTION`, `ALTERNATIVE_CLIENT_IP`, `ALTERNATIVE_FAKE_IP`:
    `yn`, `restart` + `doall`; но `ALTERNATIVE_*` меняют адресацию —
    `reinstall`;
  - `SSH_PROTECTION`, `SCAN_PROTECTION`, `TORRENT_GUARD`,
    `RESTRICT_FORWARD`, `CLIENT_ISOLATION`, `OPENVPN_BACKUP_UDP`,
    `OPENVPN_BACKUP_TCP`, `WIREGUARD_BACKUP`, `WARP_PROTECTION`,
    `VPN_DNS`: `yn` (`VPN_DNS` — `enum` по `up.sh`), `restart`;
  - `TXQUEUELEN`: `int 0..100000`, `restart`;
  - `OPENVPN_HOST`, `WIREGUARD_HOST`: `host` (домен, IP или пусто), `profiles`;
  - `MTU` (записан в конфиги OpenVPN), `ANTIZAPRET_DNS`, `*_ENABLE`,
    `OPENVPN_PATCH`, `OPENVPN_DCO`, `OPENVPN_DUPLICATE`, `OPENVPN_LOG`,
    адреса и интерфейсы, `SETUP_DATE`, ключи `*_WARP_PUBLIC_KEY`,
    `*_ENDPOINT`, `*_ADDRESS`: `reinstall` — только показ (этап 5).
  Точные перечни `enum` сверь с ветвлениями `up.sh`/`parse.sh` (тексты
  скриптов — в `testdata/`, контроллер положит их туда перед задачей) и
  укажи источник комментарием в таблице.
- `GET /v1/setup` → `[{key, value, kind, apply, title, editable}]`, без
  `*_PRIVATE_KEY`.
- `PUT /v1/setup` `{values: {KEY: value}}` — только `editable` и не
  `reinstall`; проверка всех, ошибка — ничего не записано; запись —
  замена строк `KEY=...` с сохранением порядка и прочих строк; ответ —
  какие способы применения нужны (`["doall","restart"]`), сами задачи не
  запускаются.
- Тесты: проверка каждого вида; секретов нет в ответе; запись сохраняет
  остальные строки байт в байт; `reinstall`-ключ — 400.

Коммит: «Агент: ключи setup — чтение, проверка, запись».
