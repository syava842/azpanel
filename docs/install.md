# Установка azpanel подробно

[← К README](../README.md) · [Веб-интерфейс](interface.md)

## Что делает установщик

Команда `setup.sh`:

1. Проверяет root, Linux, процессор amd64 или arm64.
2. Проверяет, что AntiZapret-VPN установлен (`/root/antizapret/client.sh`).
   Если нет, предлагает:
   1. поставить его родным установщиком
      [GubernievS/AntiZapret-VPN](https://github.com/GubernievS/AntiZapret-VPN) —
      он в конце перезагружает сервер, после этого команду нужно запустить
      ещё раз;
   2. продолжить без него — только агент прокси;
   3. выйти.
3. Скачивает последний релиз под процессор сервера, проверяет подпись
   ed25519 и контрольную сумму. Не сошлось — установка останавливается.
4. Запускает мастер `azpanel install`.

Если azpanel уже установлен, скрипт ничего не меняет и подсказывает команду
обновления.

## Вопросы мастера

Enter оставляет значение в скобках. Перед изменениями мастер показывает итог
и ждёт подтверждения; до него ничего не меняется.

| № | Вопрос | Варианты |
| --- | --- | --- |
| 1 | Что ставим | **панель + узел** (AntiZapret на этом сервере) · только узел (подключить к панели на другом сервере) · только прокси-агент · только панель |
| 3 | Адрес сервера | внешний IP определяется сам; домен — пусто, если только IP |
| 4 | Как открыть панель | **путь `/azpanel/`** в найденном nginx · отдельный порт HTTPS (8443) · только 127.0.0.1 |
| 5 | HTTPS | см. [Домен и HTTPS](#домен-и-https) |
| 6 | Администратор | логин и пароль; пустой пароль — сгенерировать |
| 10 | Бэкапы | каталог, раз в сколько дней, сколько копий хранить |
| 11 | Файрвол | какие порты открыть; правило iptables для отдельного порта — по желанию |

После установки панель доступна:

| Способ | Адрес |
| --- | --- |
| путь в nginx | `https://<домен>/azpanel/` |
| отдельный порт | `https://<домен или IP>:8443/` |
| только 127.0.0.1 | через SSH-туннель, см. [FAQ](#faq) |

Проверка: `azpanel doctor`.

## Установка без вопросов

Ответы задаются переменными `AZPANEL_*`; чего не хватает, мастер перечислит.

```bash
AZPANEL_MODE=panel+node AZPANEL_ACCESS=path AZPANEL_DOMAIN=vpn.example.com \
AZPANEL_ADMIN=admin AZPANEL_ADMIN_PASSWORD='пароль' \
  bash -c "$(curl -fsSL https://raw.githubusercontent.com/syava842/azpanel/main/scripts/setup.sh)" -- --non-interactive
```

| Переменная | Значения |
| --- | --- |
| `AZPANEL_MODE` | `panel+node`, `node`, `panel`, `proxy` |
| `AZPANEL_ACCESS` | `path`, `port`, `local` |
| `AZPANEL_DOMAIN`, `AZPANEL_ADDRESS` | домен, внешний IP |
| `AZPANEL_PORT` | порт HTTPS при `port` (по умолчанию 8443) |
| `AZPANEL_TLS` | при `port`: `existing`, `letsencrypt`, `own`, `selfsigned` |
| `AZPANEL_EMAIL` | почта для Let's Encrypt |
| `AZPANEL_CERT`, `AZPANEL_KEY` | пути к сертификату и ключу при `own` |
| `AZPANEL_ADMIN`, `AZPANEL_ADMIN_PASSWORD` | логин и пароль администратора |
| `AZPANEL_BACKUP_DIR`, `AZPANEL_BACKUP_DAYS`, `AZPANEL_BACKUP_KEEP` | бэкапы |
| `AZPANEL_SKIP_ANTIZAPRET=1` | не спрашивать про AntiZapret (сервер прокси) |
| `AZPANEL_VERSION` | конкретная версия, например `0.1.1` |

Пароль передаётся только переменной: флаг был бы виден в `ps` и в истории.

## Домен и HTTPS

Домен не обязателен: без него панель работает по IP.

| Как открыта панель | HTTPS |
| --- | --- |
| путь `/azpanel/` в nginx | сертификат того сайта nginx, к которому подключена панель; домен мастер берёт оттуда |
| отдельный порт | на выбор: уже выпущенный Let's Encrypt · новый Let's Encrypt · свой сертификат · самоподписанный (без домена — по умолчанию) |
| только 127.0.0.1 | не нужен |

Для нового сертификата Let's Encrypt нужны домен, который указывает на этот
сервер, почта и порт 80. Если на 80 уже работает nginx, проверка домена идёт
через него, остальные сайты не меняются. Продлевает certbot по своему
расписанию; после продления nginx перезагружается сам.

## Обновление и удаление

| Команда | Флаги |
| --- | --- |
| `update.sh` или `azpanel update` | `--check` — только проверить; `--yes` — без вопроса |
| `uninstall.sh` или `azpanel uninstall` | `--purge` — удалить и `/opt/azpanel`; `--yes` — без подтверждения; `--skip-backup` — без бэкапа AntiZapret |

Флаги скриптам передаются после `--`:
`bash -c "$(curl -fsSL …/update.sh)" -- --check`.

Обновление проверяет подпись, делает бэкап, ставит новую версию, проверяет,
что службы поднялись, и откатывается при сбое. Удаление делает бэкап
AntiZapret и снимает только своё: службы, хук OpenVPN, фрагмент nginx.

## Пользователи и пароли в консоли

| Команда | Что делает |
| --- | --- |
| `azpanel user list` | пользователи панели |
| `azpanel user add <логин>` | новый пользователь с ролью «пользователь» |
| `azpanel user add <логин> --admin` | новый администратор |
| `azpanel user reset <логин>` | новый случайный пароль, 2FA выключить, сессии завершить |
| `azpanel panel passwd --user <логин>` | задать свой пароль (спросит дважды, без вывода на экран) |

`user add` и `user reset` печатают случайный пароль один раз; при первом
входе панель потребует его сменить. Логин — 3–32 знака: строчные латинские
буквы, цифры и `_ . -`.

## Файлы и службы

| Путь | Что |
| --- | --- |
| `/opt/azpanel/bin/azpanel` | программа; ссылка `/usr/local/bin/azpanel` |
| `/opt/azpanel/etc/config.toml` | настройки (их же правит страница «Настройки») |
| `/opt/azpanel/etc/secrets.env` | секреты, только root |
| `/opt/azpanel/etc/install.env` | ответы мастера без секретов — подставляются при переустановке |
| `/opt/azpanel/data/` | база панели, лимиты, история |
| `/opt/azpanel/log/` | `node.log`, `panel.log` |
| `/opt/azpanel/backup/` | бэкапы |
| `azpanel-node`, `azpanel-panel` | службы systemd |

## FAQ

<details>
  <summary>Как открыть панель, установленную «только на 127.0.0.1»?</summary>

Через SSH-туннель с компьютера:

```bash
ssh -L 8080:127.0.0.1:8080 root@<сервер>
```

и откройте `http://127.0.0.1:8080/`.

</details>

<details>
  <summary>Как изменить адрес, порт или префикс панели?</summary>

Повторите мастер: `azpanel install`. Прежние ответы подставятся из
`install.env`, поменяйте нужные. `panel.base_path` и `panel.listen` можно
поменять и на странице **Настройки**: изменение применяется с таймером
возврата, если его не подтвердить.

</details>

<details>
  <summary>Панель не открывается снаружи</summary>

1. `azpanel doctor` покажет, что не так: службы, nginx, сертификат, диск.
2. На отдельном порту проверьте файрвол и правила облака: порт (8443 по
   умолчанию) должен быть открыт для входящих.
3. Проверьте **Настройки → Доступ**: при белом списке вход разрешён только с
   этих адресов.

</details>

<details>
  <summary>Браузер пишет, что сертификат недействителен</summary>

`azpanel doctor` покажет срок сертификата. Let's Encrypt не продлится, если
домен больше не указывает на этот сервер или порт 80 закрыт. При пути в
nginx сертификат принадлежит сайту nginx — продлевайте его там.

</details>

<details>
  <summary>Где журналы?</summary>

`/opt/azpanel/log/node.log` и `panel.log`, а также `journalctl -u azpanel-node`
и `journalctl -u azpanel-panel`. Действия пользователей — в панели, раздел
**Журнал**.

</details>

<details>
  <summary>Команда azpanel не найдена</summary>

Ранние сборки (до 0.1.0) не ставили ссылку в PATH. Запускайте
`/opt/azpanel/bin/azpanel` или создайте ссылку:
`ln -s /opt/azpanel/bin/azpanel /usr/local/bin/azpanel`.

</details>

<details>
  <summary>Что azpanel меняет в системе?</summary>

Только своё: `/opt/azpanel`, две службы, хук OpenVPN для лимитов, фрагмент
nginx (если выбран nginx) и сертификат (если выбран выпуск). Скрипты и
настройки AntiZapret меняются только вашими действиями в панели — теми же
скриптами AntiZapret.

</details>

## Безопасность

- Релизы подписаны ключом ed25519; `setup.sh` и `azpanel update` проверяют
  подпись и сумму до установки.
- Установщик AntiZapret-VPN запускается из `GubernievS/AntiZapret-VPN`
  (ветка `main`) так же, как в его README: этот шаг подписью azpanel не
  проверяется.
- Пароли хранятся хешами, вход защищён от перебора, есть двухфакторный вход и
  белый список адресов. Страницы отдаются со строгой CSP.
